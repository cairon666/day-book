# Spec Delta

## ADDED Requirements

### Requirement: Деплой API-образа

Пайплайн ДОЛЖЕН (MUST) собирать и публиковать образ API-сервера в GHCR с теми же правилами версионирования, что и образ веб-приложения (теги `main` и `<sha>`), и развертывать его на сервере в том же деплой-контуре. При падении сборки любого из образов деплой НЕ ДОЛЖЕН (MUST NOT) выполняться.

#### Scenario: Успешный деплой обоих приложений

- **WHEN** в `main` пушатся изменения, затрагивающие любое из приложений
- **THEN** образы `web` и `api` собираются и публикуются, оба контейнера на сервере обновляются

#### Scenario: Упала сборка API

- **WHEN** сборка или проверка типов API-сервера завершилась ошибкой
- **THEN** образ `api` не публикуется, продакшн остаётся на предыдущих версиях обоих контейнеров

### Requirement: Сервис PostgreSQL с постоянным хранением

На сервере и локально ДОЛЖЕН (MUST) работать сервис PostgreSQL с healthcheck-проверкой готовности; данные ДОЛЖНЫ (MUST) переживать пересоздание контейнера (том) и перезагрузку сервера. Сервис API НЕ ДОЛЖЕН (MUST NOT) начинать работу до готовности базы данных.

#### Scenario: Данные переживают пересоздание

- **WHEN** контейнер PostgreSQL пересоздан (например, обновление образа)
- **THEN** данные, записанные до пересоздания, доступны после

#### Scenario: Порядок старта

- **WHEN** стек поднимается при неготовой базе данных
- **THEN** сервис API ожидает готовности PostgreSQL и только затем выполняет подключение

### Requirement: Автоматическое применение миграций

При каждом развёртывании API миграции схемы базы данных ДОЛЖНЫ (MUST) применяться автоматически и идемпотентно до начала приёма запросов; уже применённые миграции НЕ ДОЛЖНЫ (MUST NOT) выполняться повторно.

#### Scenario: Первый деплой с новой миграцией

- **WHEN** разворачивается версия API, содержащая миграции, которых нет в базе
- **THEN** миграции применяются до старта приёма запросов, health-проверка отвечает 200

#### Scenario: Повторный деплой без новых миграций

- **WHEN** контейнер API перезапущен, а база уже содержит все миграции версии
- **THEN** шаг миграций завершается без изменений, приложение стартует

### Requirement: Маршрутизация `/api/*` на сервере

Запросы к `https://day-book.cairon.ru/api/*` ДОЛЖНЫ (MUST) проксироваться host-nginx'ом в контейнер API. Сервис API ДОЛЖЕН (MUST) быть доступен только с хоста (loopback), внешний доступ — исключительно через TLS-прокси, как и веб-приложение.

#### Scenario: Запрос к API через домен

- **WHEN** выполнен запрос `GET https://day-book.cairon.ru/api/health`
- **THEN** прокси передаёт запрос контейнеру API и возвращает его ответ

#### Scenario: Прямой доступ извне

- **WHEN** выполняется подключение к порту API-контейнера снаружи сервера
- **THEN** соединение недоступно (порт не проброшен наружу)
