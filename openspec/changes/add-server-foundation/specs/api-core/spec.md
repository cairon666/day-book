# Spec Delta

## Purpose

Каркас API-сервера day-book: операционный контракт бэкенда — проверка готовности (health), защита от старта с неверной конфигурацией, единый формат ошибок и предсказуемое завершение работы.

## ADDED Requirements

### Requirement: Health-проверка

Система ДОЛЖНА (MUST) предоставлять публичный эндпоинт `GET /api/health`, который сообщает о готовности процесса и доступности базы данных без аутентификации.

#### Scenario: Приложение и БД доступны

- **WHEN** выполнен запрос `GET /api/health`, пока приложение работает и база данных отвечает
- **THEN** ответ имеет статус 200 и содержит статус приложения `ok` и статус базы данных `up`

#### Scenario: База данных недоступна

- **WHEN** база данных не отвечает на проверку соединения
- **THEN** ответ имеет статус 503 и содержит статус базы данных, отличный от `up`

### Requirement: Проверка окружения при старте

Приложение ДОЛЖНО (MUST) проверять все обязательные переменные окружения до начала приёма запросов: при отсутствующем или невалидном значении процесс завершается с ненулевым кодом и понятным сообщением о причине.

#### Scenario: Отсутствует обязательная переменная

- **WHEN** приложение запущено без обязательной переменной окружения (например, строки подключения к БД)
- **THEN** процесс завершается с ненулевым кодом выхода, в выводе указано имя переменной, HTTP-порт не открывается

#### Scenario: Корректное окружение

- **WHEN** все обязательные переменные заданы и валидны
- **THEN** приложение стартует и начинает принимать запросы

### Requirement: Единый формат ошибок

Все ошибки API ДОЛЖНЫ (MUST) возвращаться в едином JSON-формате, содержащем HTTP-статус и человекочитаемое сообщение. Детали внутреннего устройства (стектрейсы, SQL, пути в файловой системе) НЕ ДОЛЖНЫ (MUST NOT) раскрываться в ответах.

#### Scenario: Неизвестный маршрут

- **WHEN** выполнен запрос к несуществующему пути под префиксом `/api`
- **THEN** возвращается статус 404 в едином JSON-формате ошибок

#### Scenario: Внутренняя ошибка

- **WHEN** при обработке запроса возникает непредвиденное исключение
- **THEN** возвращается статус 500 в едином JSON-формате, без стектрейса и внутренних деталей; подробности фиксируются в логах процесса

### Requirement: Префикс `/api`

Все эндпоинты сервера ДОЛЖНЫ (MUST) обслуживаться под префиксом `/api`. Запросы вне префикса ДОЛЖНЫ (MUST) возвращать 404.

#### Scenario: Запрос вне префикса

- **WHEN** выполнен запрос `GET /health` без префикса `/api`
- **THEN** возвращается статус 404

### Requirement: Корректное завершение работы

При получении сигнала остановки (SIGTERM/SIGINT) приложение ДОЛЖНО (MUST) прекратить приём новых соединений, завершить начатые запросы и закрыть соединения с базой данных до выхода процесса.

#### Scenario: Остановка контейнера

- **WHEN** процесс получает SIGTERM во время обслуживания запросов
- **THEN** начатые запросы завершаются ответами, соединения с БД закрываются, процесс завершается без аварийных сообщений от драйвера БД
