# Design

## Context

Greenfield-репозиторий; собственный сервер с уже настроенным TLS (nginx на хосте, домен `day-book.cairon.ru`); бот в BotFather; требование бесплатного CI. Реализация уже выполнена (коммит `782852f`), этот документ фиксирует принятые решения. Мотивация — в `proposal.md`.

## Goals / Non-Goals

**Goals:**

- Минимальный обслуживающий контур: деплой без ручных действий на сервере после первичной настройки.
- Структура репозитория, расширяющаяся до api/воркеров/БД без переделки.
- Предсказуемый откат версий.

**Non-Goals:**

- Бэкенд, авторизация, TMA SDK (отдельные будущие изменения).
- Blue-green / zero-downtime деплой.
- Мониторинг и алертинг.

## Decisions

1. **Статика в проде, Node — только стадия сборки.** Приложение — чистый SPA без серверной логики; nginx-образ отдаёт `dist/`. Альтернатива — Node-сервер: сложнее, больше поверхность атаки, не нужна сейчас.
2. **pnpm workspace (`apps/*`) с первого дня.** Планируются `apps/api` и др.; workspace стоит почти бесплатно, а переход от одиночного пакета позже — лишний churn.
3. **Многостадийный Dockerfile: сначала манифесты + `--frozen-lockfile`, затем исходники.** Слой `pnpm install` кэшируется при неизменных зависимостях; lockfile гарантирует воспроизводимость. Альтернатива `npm i -g pnpm` вместо corepack — отвергнута: corepack читает версию из `packageManager`, единый источник версии.
4. **TLS терминирует nginx на хосте; контейнер слушает `127.0.0.1:8080`.** Минимальное изменение существующей инфраструктуры (не трогаем сертификаты). Альтернатива — Caddy-контейнер: потребовала бы миграции TLS и конфликта портов с host-nginx.
5. **CI: GitHub Actions → GHCR → SSH-деплой.** Бесплатно, нуль обслуживания. Альтернативы (self-hosted runner, сборка на сервере) сложнее без выгоды на этом этапе. Образ публикуется с тегами `main` + `<sha>` (откат по sha).
6. **Один `docker-compose.yml` для локального прогона и сервера.** Различие только в переменной `WEB_IMAGE` (`.env` на сервере указывает на ghcr-образ; локально по умолчанию собирается `day-book-web:local`).
7. **Кэширование: `/assets/` — `immutable`, 1 год; `index.html` — без долгого кэша.** Vite хэширует ассеты; смена деплоя видна сразу через свежий `index.html`.
8. **Strict-режим TS (`noUncheckedSideEffectImports` и пр.).** Ранний барьер ошибок. Грабля: CSS-импорт требует `src/vite-env.d.ts` со ссылкой на `vite/client`, иначе TS2882.

## Risks / Trade-offs

- [Приватный образ в GHCR требует авторизации на сервере] → разовый `docker login ghcr.io` с PAT (scope `read:packages`); задокументировано в tasks.
- [Верхний регистр в имени репозитория ломает push в GHCR] → шаг lowercase-нормализации имени образа в workflow.
- [Занятость порта 8080 на сервере] → проверить перед первым деплоем; при конфликте менять порт в `docker-compose.yml` и site-конфиге nginx.
- [SSH-ключ как секрет CI] → выделенный ключ только для деплоя, область доступа ограничена одним каталогом.
- [Секундный даунтайм при `up -d`] → приемлемо для этапа «Привет»; устраняется blue-green в будущем.

## Migration Plan

Первичный разворот: ручные шаги сервера/GitHub/BotFather (см. `tasks.md`, разделы 2–5). Откат: `git revert` в `main` (пайплайн откатит версию) либо вручную `WEB_IMAGE=...:<предыдущий sha>` на сервере и `docker compose up -d`.
