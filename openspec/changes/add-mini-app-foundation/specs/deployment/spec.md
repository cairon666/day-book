# Spec Delta

## Purpose

Контейнерная сборка и автоматический деплой day-book: путь от коммита в `main` до работающего приложения на собственном сервере, поведение контейнера в продакшне и защита секретов.

## ADDED Requirements

### Requirement: Автоматический деплой по push в main

При push в ветку `main` система ДОЛЖНА (MUST) автоматически собрать образ приложения, опубликовать его в реестр GHCR и обновить контейнер на сервере. При падении любого этапа пайплайна деплой НЕ ДОЛЖЕН (MUST NOT) выполняться.

#### Scenario: Успешный деплой

- **WHEN** в `main` запушены изменения и пайплайн прошёл успешно
- **THEN** новая версия приложения доступна на `https://day-book.cairon.ru`

#### Scenario: Упавшая сборка

- **WHEN** этап сборки или проверки типов завершился ошибкой
- **THEN** образ не публикуется, продакшн остаётся на предыдущей версии

### Requirement: Версионирование образов

Каждый успешный деплой ДОЛЖЕН (MUST) публиковать образ с тегом `main` и дополнительным тегом с хэшем коммита, чтобы любую версию можно было отличить и откатить.

#### Scenario: Идентификация версии

- **WHEN** пайплайн успешно собрал образ для коммита X
- **THEN** в реестре появились теги `main` и `<sha коммита X>` для одного и того же образа

### Requirement: Изолированный контур контейнера

Контейнер веб-приложения ДОЛЖЕН (MUST) быть доступен только с хоста сервера (привязка к loopback). Внешний доступ ДОЛЖЕН (MUST) проходить исключительно через TLS-прокси на хосте сервера.

#### Scenario: Доступ через домен

- **WHEN** выполнен запрос к `https://day-book.cairon.ru`
- **THEN** прокси хоста передаёт запрос контейнеру и возвращает ответ приложения

#### Scenario: Прямой доступ извне

- **WHEN** выполняется подключение к портам контейнера снаружи сервера
- **THEN** соединение недоступно (порты не проброшены наружу)

### Requirement: Автовосстановление контейнера

Контейнер ДОЛЖЕН (MUST) автоматически перезапускаться при падении процесса и подниматься после перезагрузки сервера (политика `unless-stopped`).

#### Scenario: Падение процесса

- **WHEN** процесс веб-сервера в контейнере завершился аварийно
- **THEN** контейнер перезапускается автоматически

#### Scenario: Перезагрузка сервера

- **WHEN** сервер перезагружен
- **THEN** приложение поднимается без ручных действий

### Requirement: Секреты не покидают репозиторий и образ

Секреты НЕ ДОЛЖНЫ (MUST NOT) попадать в git-историю и в публикуемые образы. Доступы для деплоя ДОЛЖНЫ (MUST) передаваться только через секреты CI (GitHub Actions Secrets).

#### Scenario: Коммит с .env

- **WHEN** в рабочей директории присутствует `.env`
- **THEN** файл исключён из git и из контекста сборки образа

#### Scenario: Образ не содержит секретов

- **WHEN** образ собран и опубликован
- **THEN** файлы `.env` и значения секретов отсутствуют в слоях образа
