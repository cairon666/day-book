# Spec Delta

## Purpose

Фронтенд Telegram Mini App day-book: доступность приложения из Telegram по защищённому адресу и базовое поведение веб-страниц (приветствие, SPA-навигация, кэширование статики).

## ADDED Requirements

### Requirement: Открытие приложения через кнопку бота

Mini App ДОЛЖНО (MUST) открываться в Telegram по кнопке бота (Menu Button) по адресу `https://day-book.cairon.ru` с валидным TLS-сертификатом. Домен приложения ДОЛЖЕН (MUST) быть привязан к боту в BotFather.

#### Scenario: Открытие с телефона

- **WHEN** пользователь открывает бота в Telegram и нажимает кнопку Menu Button
- **THEN** приложение открывается внутри Telegram по адресу `https://day-book.cairon.ru` без TLS-ошибок

#### Scenario: Домен не привязан к боту

- **WHEN** домен приложения не указан в настройках бота в BotFather
- **THEN** Telegram не открывает приложение по кнопке

### Requirement: Страница-приветствие

Приложение ДОЛЖНО (MUST) отображать приветственную страницу («Привет!») на главном экране. Страница ДОЛЖНА (MUST) оставаться читаемой в светлой и тёмной темах.

#### Scenario: Главное окно

- **WHEN** приложение открыто
- **THEN** отображается приветствие по центру экрана

#### Scenario: Тёмная тема устройства

- **WHEN** у устройства включена тёмная тема
- **THEN** страница остаётся читаемой (текст и фон адаптируются)

### Requirement: SPA-фоллбэк для неизвестных маршрутов

Веб-сервер ДОЛЖЕН (MUST) отвечать `index.html` с кодом 200 на запрос любого несуществующего пути (клиентская маршрутизация), кроме путей хэшированных ассетов.

#### Scenario: Неизвестный путь

- **WHEN** выполнен запрос `/some/unknown/route`
- **THEN** сервер отвечает кодом 200 и отдаёт `index.html`

#### Scenario: Отсутствующий ассет

- **WHEN** выполнен запрос несуществующего файла из `/assets/`
- **THEN** сервер отвечает кодом 404

### Requirement: Кэширование статики

Хэшированные ассеты ДОЛЖНЫ (MUST) отдаваться с `Cache-Control: public, max-age=31536000, immutable`. `index.html` НЕ ДОЛЖЕН (MUST NOT) кэшироваться на долгий срок, чтобы после деплоя пользователи сразу получали новую версию.

#### Scenario: Повторная загрузка ассета

- **WHEN** ассет из `/assets/` запрошен повторно
- **THEN** ответ содержит заголовок долгосрочного неизменяемого кэша

#### Scenario: После деплоя новой версии

- **WHEN** опубликована новая версия приложения
- **THEN** следующий запрос главной страницы отдаёт новый `index.html` со ссылками на новые ассеты
